Data Directory — Deepfake Detection

1. Purpose

The "data/" directory contains metadata and information required to access and organise the processed face-crop dataset used in our Deepfake Detection project.

The face-crop dataset is already available on Kaggle, with the training, validation and testing ZIP archives extracted into their respective folders.

Team members can therefore use the existing Kaggle dataset directly for model training without repeating the entire preprocessing process.

This directory also documents the metadata generated by our preprocessing pipeline.

---

2. Where Is Our Dataset Available?

The processed face-crop dataset is hosted on Kaggle.

Kaggle Dataset: [https://www.kaggle.com/datasets/joy1008/deepfake-face-crops]

The dataset contains three splits:

- "train" — Training data.
- "val" — Validation data.
- "test" — Testing data.

Each split contains extracted face crops belonging to the real and fake classes.

---

3. How to Access the Kaggle Dataset

Option 1: Using Kaggle Notebooks (Recommended)

1. Open the Kaggle dataset link.
2. Click New Notebook or open your existing notebook.
3. In the notebook, select Add Input.
4. Search for our Deepfake Detection face-crop dataset.
5. Add the dataset to your notebook.
6. Access the files through the "/kaggle/input/" directory.

Example:

from pathlib import Path

DATASET_DIR = Path("/kaggle/input/deepfake-face-crops")

TRAIN_DIR = DATASET_DIR / "train"
VAL_DIR = DATASET_DIR / "val"
TEST_DIR = DATASET_DIR / "test"

print("Train:", TRAIN_DIR.exists())
print("Validation:", VAL_DIR.exists())
print("Test:", TEST_DIR.exists())

You can inspect the available folders using:

for path in DATASET_DIR.iterdir():
    print(path.name)

Option 2: Downloading the Dataset Locally

1. Open the Kaggle dataset page.
2. Download the dataset.
3. Extract the downloaded archive.
4. Keep the train, validation and test folders organised.
5. Update the dataset paths in your training scripts.

Example:

from pathlib import Path

DATASET_DIR = Path("path/to/dataset")

TRAIN_DIR = DATASET_DIR / "train"
VAL_DIR = DATASET_DIR / "val"
TEST_DIR = DATASET_DIR / "test"

5. Metadata File Descriptions

A. split_assignment.csv

This is a video-level metadata file generated during identity-aware dataset splitting.

Each row represents one video.

Column| Description
"video_path"| Original location of the video
"uid"| Unique identifier of the video
"label"| Video category: real or fake
"split"| Assigned split: train, val or test

When to use it:

- Inspect video assignments.
- Check real/fake distribution.
- Investigate identity leakage.
- Understand how videos were distributed across splits.

B. manifest_train.csv

Contains frame-level metadata for the training dataset.

C. manifest_val.csv

Contains frame-level metadata for the validation dataset.

D. manifest_test.csv

Contains frame-level metadata for the testing dataset.

Each row represents a sampled frame.

Column| Description
"path"| Image path inside the corresponding ZIP archive
"label"| 0 = real, 1 = fake
"split"| Train, validation or test
"video_id"| Source video identifier
"frame_idx"| Sampled frame index
"face_found"| Whether MTCNN detected a face
"x1", "y1"| Top-left bounding box coordinates
"x2", "y2"| Bottom-right bounding box coordinates
"prob"| MTCNN detection confidence

When to use them:

- Training: "manifest_train.csv"
- Validation: "manifest_val.csv"
- Final evaluation: "manifest_test.csv"

E. manifest.csv

Contains the combined frame-level records from all three splits.

Use it for overall dataset analysis and statistics. Prefer individual manifests during model training and evaluation.

---

6. Understanding the Labels

Label| Meaning
0| Real
1| Fake

The video-level assignment CSV uses text labels ("real", "fake"), while the frame-level manifests use numeric labels.

7. Loading the Dataset for Model Training

A. Loading images directly from extracted folders

If the Kaggle dataset contains the extracted "train", "val" and "test" directories:

from pathlib import Path

DATASET_DIR = Path("/kaggle/input/<dataset-folder-name>")

TRAIN_DIR = DATASET_DIR / "train"
VAL_DIR = DATASET_DIR / "val"
TEST_DIR = DATASET_DIR / "test"

REAL_DIR = TRAIN_DIR / "real"
FAKE_DIR = TRAIN_DIR / "fake"

You can access the image files using:

real_images = list(REAL_DIR.glob("*"))
fake_images = list(FAKE_DIR.glob("*"))

print("Real images:", len(real_images))
print("Fake images:", len(fake_images))

For nested folders, use "rglob("*")" instead of "glob("*")".

B. Loading the manifests using Pandas

import pandas as pd

train_df = pd.read_csv(
    "data/manifests/manifest_train.csv"
)

val_df = pd.read_csv(
    "data/manifests/manifest_val.csv"
)

test_df = pd.read_csv(
    "data/manifests/manifest_test.csv"
)

print(train_df.head())

Important: The manifest "path" values refer to members of the corresponding ZIP archives. If you use an already extracted Kaggle dataset instead, construct image paths using its actual directory structure. Do not assume the manifest paths are directly usable as filesystem paths.

---

8. Important Precautions

1. Do not randomly split the existing dataset again. The project uses identity-aware splitting to reduce identity leakage.
2. Keep training, validation and testing data separate.
3. Do not use test data for training or hyperparameter tuning.
4. Check "face_found" before loading images through the manifests.
5. Preserve the original labels: 0 = real and 1 = fake.
6. Do not manually modify generated manifests.
7. Avoid keeping multiple unnecessary copies of the face-crop dataset.
8. Do not upload large datasets or ZIP archives unnecessarily to GitHub.
9. Make sure all team members use the same dataset version to ensure consistent experiments.

9. Generating the Dataset Yourself

If you want to reproduce the preprocessing workflow instead of using the existing Kaggle dataset, run the pipeline from the project root.

For a small test run:

python -m preprocessing.build_dataset --limit 20

After verifying the results, run the complete pipeline:

python -m preprocessing.build_dataset

The pipeline performs:

1. Official FaceForensics++ split loading.
2. Identity-aware video splitting.
3. Leakage checking.
4. Frame extraction.
5. MTCNN face detection.
6. Largest-face selection and cropping.
7. ZIP archive generation.
8. CSV manifest generation.

Refer to "preprocessing/README_PREPROCESSING.md" for detailed instructions.

10. For New Team Members

Before starting model development:

1. Access the Kaggle face-crop dataset.
2. Add it to your Kaggle notebook or download it locally.
3. Verify the train, validation and test directories.
4. Understand the real/fake label convention.
5. Use the correct split for your experiment.
6. Refer to the manifests when you need frame-level metadata or face detection information.

Remember: The Kaggle dataset provides ready-to-use face crops. The preprocessing pipeline allows us to reproduce the dataset generation process when necessary. Both approaches should follow the same dataset split and label conventions.
